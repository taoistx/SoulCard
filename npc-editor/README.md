# 对话编辑器：节点图与文本

双击“启动剧情编辑器.cmd”打开编辑器。节点图与文本模式编辑同一份 NPC／世界对话 JSON，游戏仍由现有对话运行时执行。启动 Demo 和节点地图编辑器的本地服务也支持相同的对话文件夹设置与保存接口。

启动批处理会依次检测 `py -3`、`python`、`python3` 中可用的 Python 3.10+，每次分配新端口，并在服务绑定端口后打开实际地址。它不会复用 8000 端口的旧静态服务；启动失败时窗口会保留错误信息。编辑期间保持这个服务窗口开启。设置中若提示“未连接文件夹读写服务”，请使用启动脚本自动打开的新页面；同一页面的服务恢复后，也可点击“重新检测连接”，已填写路径会保留。

## 对话文件夹与直接保存

顶部“设置”填写对话 JSON 所在文件夹，可以使用绝对路径或项目根目录下的相对路径。点击“应用设置并读取”后，会扫描该文件夹直属的全部 `.json`，将通过对话运行时格式校验的 NPC／世界对话放入左侧列表。无需编辑 manifest；非对话文件会忽略，无效文件和同类型重复 ID 会提示并跳过。空文件夹也可打开，随后新建或导入对话。

设置保存在项目根目录的 `.npc-editor-settings.json`（已加入 Git 忽略），重启浏览器或本地服务后继续读取同一文件夹。首次未配置时使用 `npc-editor/examples`。设置的文件夹被移动或删除后，启动错误面板提供“设置 JSON 文件夹”用于恢复。

节点图画布上方有独立工具栏，点击“生效并应用到Json”会校验并写回源文件；文本模式先“转换并应用 JSON”，再“保存到 JSON 文件”，存在未转换草稿时会提示处理。已有对话保留原文件名，新建对话写入 `<ID>.json`。修改 ID 仍写回原文件，外部引用需要自行同步。顶部原有“导出当前对话”已移除，不再下载 JSON。

只有文件写入成功才标记“已保存”。文件被外部修改、同名文件已存在、文件夹改变或写入失败时保留当前编辑并显示错误，不覆盖磁盘内容。每个文件夹的会话草稿独立保存，恢复时核对源文件版本，避免旧节点草稿覆盖外部修改。保存其他对话不影响当前未保存草稿。

普通静态服务器只支持范例预览，不能读取任意本地目录或直接写回文件；请使用上述本地启动脚本。直接双击 HTML 时仍可在错误面板手动选择范例进行预览和转换。原有完整文本和 Flag 映射的导入导出继续作为写作辅助功能。

打开“状态沙盒”可点击“调整测试状态”，测试理解感染、吃药康复、重置 Flag 等状态；“问候 → 继续追问”测试进入正文时获得“露西怪兽”；“回避”测试保留失望回复、复用 mainChoices 选项。检查仅验证对话本身，不提示地图摆放、manifest 或战斗角色缺失。此阶段优先调整文本逻辑，不推广至现有 NPC 或节点图。

仅历史项目集成回归使用显式参数 `?source=project`；默认入口使用配置的文件夹，不强制加载地图、战斗或项目 manifest。在历史入口应用文件夹设置后，会切换到文件夹编辑模式。

## 写作示例

```text
露西看向你
》回避
    她非常失望，但又不愿意表现出来
    @ mainChoices
》（理解感染/！（吃药&已经康复））你好点吗？
    她摇摇头，似乎很难受
》问候（+问候过露西）
    她没有回答
    》继续追问
        她变成了怪兽
        （+露西怪兽）
    》离开
》离开
```

第一行也是正文，对话名称保留在“对话与入口设置”中。同一节点的正文和选项使用相同缩进，选项只多一个 `》` 前缀。选项的下一段回复增加一级 Tab 或四个空格，该回复的选项保持与回复同级；减少缩进回到外层分支。连续正文组成一个节点，直接留空行即可分段，转换 JSON 时自动保留正文段落之间的空行（包括连续多个空行），无需输入转义符。此前的顶格回复简写仍可读取，但推荐明确缩进。

点击行号旁的箭头可以折叠或展开选项的后续分支，选项行和原始行号会保留。转换和导出使用完整文本。点击转换诊断会展开对应分支并定位到问题行。

光标所在行用较深的底色标出，同一分支里的正文和选项用浅色标出。左侧紫线标记引出当前分支的上一级选项。

在引用行行首输入 `@`（可带缩进），会列出当前对话 JSON 的节点和选项组 ID。继续输入 ID 前缀可筛选，按上下键选择、Enter 或 Tab 插入，也可直接点击；Esc 关闭候选。旧版文本格式的节点跳转会插入其原有的 `-> ID` 写法。

```text
主文本1
》主文本1选项1
    主文本2
    》主文本2选项1
    》主文本2选项2
》离开
```

条件放在 `》` 后、选项文字前。`&`／`＆` 表示全部满足，`/`／`／` 表示任意满足，`!`／`！` 表示取反；支持半角／全角括号及混用、多层嵌套。优先级为括号、取反、全部满足、任意满足。例如 `条件1/！（条件2&条件3）` 只在条件1为假、条件2和条件3都为真时不满足。不满足时隐藏回答。正向 Flag 条件检查值是否为 `true`；未设置或为假时满足取反条件。中文“没有吃药”是独立名称，不自动解释成否定。

回答末尾的 `（+名称）` 在选择时设置 Flag，正文独立一行的同样写法在进入节点时设置。`（-名称）` 将值设为 `false`，不会删除字段；多个效果依次执行。没有后续内容或跳转的回答结束该分支，末尾正文沿用游戏的关闭规则，NPC 献祭入口仍由 World 自动追加。

## 转换与草稿

正文编辑框自动延伸到窗口底部的页签栏上方，窗口变化时同步伸缩，长文本在编辑框内部滚动。底部的“正文／高级配置／Flag 映射／语法帮助／当前 JSON”页签共用整块中间面板；切换保留输入、光标和滚动位置，不触发转换。页签可用左右方向键、Home、End 切换。

输入时只保存文本草稿，不实时解析、生成 Flag 或转换 JSON。内容确定后点击“转换并应用 JSON”，才检查语法并更新当前 JSON；出错时显示行列位置，保留文本与原 JSON。一次转换可以撤销。节点图、状态沙盒、检查和 JSON 文件保存使用已转换的内容。切换视图、切换对话、打开沙盒或保存文件时，会提示处理尚未转换的草稿，可手动转换、保留或放弃。草稿保存在当前浏览器会话，刷新后可恢复。

若保留草稿后又修改节点图，应用旧草稿会被阻止。先导出完整文本，再从节点图重新生成并合并修改。完整文本草稿可在存在语法错误时导出；高级配置本身须为有效 JSON。

## 自动 ID 与跳转

正文中不要声明节点 ID 或选项 ID。点击转换后，系统为正文节点和回答自动分配 ID，左侧目录按正文顺序显示摘要和 ID；点击目录可在右侧查看只读节点 ID。再次转换时，系统优先按原正文和位置保留已有身份，新增节点再获得新 ID，不复用已删除节点的编号。这些对应关系放在辅助配置中，不插入正文。

调试范例现在验证独立的 `nodes` 与 `optionLists`：node 保存正文、进入效果及 `optionList` 引用；选项组统一保存 `options`。开场与失望回复共用 `mainChoices`，不再复制选项，也不再使用 `editor.textAuthoring.optionSources`。节点图编辑共享选项会立即影响全部引用节点。

统一使用 `@ID` 或 `@ ID`，根据目标类型判断。JSON 生成文本时，直接跳转的 `@nodeId` 与它前面的选项同级，不额外增加缩进；旧文本中多缩进一层的引用仍可读取：

- `@root` 引用 node：直接进入开场，显示目标正文并执行目标进入效果。即使前面写了回复正文，也会被目标正文替换，转换时给出提示。
- 回复正文后写 `@mainChoices` 引用 optionList：保留自己的正文与进入效果，只使用共享回答组。
- 回答下只有 `@mainChoices`：保留当前显示的正文并更换回答组，不重复执行原节点进入效果。
- `@` 不能引用单个 option；未知 ID、node／optionList 重名会阻止转换，原 JSON 不变。不能同时引用回答组和写自有回答。

左侧目录显示 `nodeId · @optionListId`，节点属性可选择共享选项组。普通回答依然直接写在正文中，转换时自动创建和保留组 ID，无需手写组声明。完整文本导出包含 `syntaxVersion: 4` 及辅助配置，支持导入后继续编辑；已知引用目标即使不再展开在正文中，也会保留其被引用的节点及必要分支。选项重排或插入时优先按唯一的选项文字保留 ID 和高级配置；同名选项仍应避免同时重排和改名。

文件夹模式使用简写正文语法；历史项目入口继续使用旧数据与语法，不会迁移或改写游戏对话。

## 辅助配置

在选项的下一行同级写 `#调用ID`，例如：

```text
》（交易知识）交易
#shop_eddie
```

每个选项可调用一个已登记的模块动作，转换后保存为该选项的 `action` 字段，导出时恢复为 `#调用ID`。打开艾迪商店的选项在调用行结束，正文行开头需要显示字面 `#` 时写成 `\#`。

高级 JSON 配置保留节点标题、提示、物品效果、具名动作、入口规则、文本变体和布局。正文写默认文本，高级配置保留其变体。选项条件或效果无法用简写完整表达时，整体保留在高级配置。不要在两处重复定义同一字段，转换会报错。新增递归条件组为 `{ "mode": "all" | "any" | "not", "clauses": [...] }`，子项可以是原有叶子条件或条件组，`not` 必须恰有一个子项。节点图属性面板也支持子组和取反。

导出的完整文本在末尾以 `@config`、`@end` 包围辅助配置；导入会恢复两个区域。普通正文若以 `》`、`@` 开头，或需使用语法括号，可加反斜杠转义；条件名称中的运算符也可转义，例如 `道路\/感染` 表示名称“道路/感染”。正文段落之间直接留空行即可；旧文本中的单独反斜杠仍兼容为空正文行。默认文本模式不再使用 `@node`、`@option` 声明；历史项目集成回归暂时沿用旧语法，后续再处理推广兼容。

## 中文 Flag 映射

手动转换时，首次使用的中文名称会自动获得确定性的 `storyFlag_<完整SHA-256摘要>` 字段。同名跨对话共用字段。需要接入已有 World Flag 时，在共享映射中先添加中文名称与该字段的对应关系，点击“采用映射”，再手动转换。已经登记的名称不能改绑字段；改显示名称时保留字段，并同步修改正文中的名称。冲突或无效文本不会部分应用。

连接 JSON 文件夹后，该目录下的 `flag-mappings.json` 统一保存名称到字段的映射。点「采用映射」或导入映射会立即保存，文本转换成功后也会保存新生成的映射。切换目录会读取目标目录的映射表。目录首次建立映射表时，会收集同目录旧对话的 `editor.textAuthoring.flagAliases` 和当前会话里该目录的旧映射。已有映射表时以文件为准，重新保存对话时清除对应的旧别名元数据。改名只需保存映射表，未转换的文本草稿需要同步修改名称。

映射区支持独立导入导出，完整文本仍携带它使用的映射。静态预览沿用会话草稿和对话内的映射，可通过本地启动脚本使用目录级存储。

直接保存不会自动登记游戏 manifest 或修改地图。接入游戏时，新增对话仍按项目约定登记 manifest、调用入口及 NPC 战斗角色配置。
