## 1. 使用这份文档的方法

设计新需求时，先查第 2 节的能力表，再用第 8 节模板写清触发、成本、结果和重访状态，最后按第 7 节确定配置及代码落点。

当前项目是**纯前端、固定节点路网探索的轻量 RPG 原型，内含独立的时间轴卡牌战斗**。核心循环已具备：

`探索地点 → NPC 对话 / 卡槽行动 / 直接战斗 → 世界后果 → 返回地图 → 长休推进一天`

它适合继续扩写有限地点、人物分支和局部因果。通用任务日志、人物关系数值、全局日程、设施模拟、完整经济和游戏存档目前尚未实现。

评估完成度时，应分别确认：

| 层次 | 判断方式 | 常见误判 |
|---|---|---|
| 系统能力 | 运行时能解释对应输入和后果 | 有 Flag 不等于有完整关系系统 |
| 内容配置 | JSON / 地图数据中有定义 | 有 NPC 文件不等于地图能到达他 |
| 实际接入 | 起点可达、事件挂载、条件可满足、结果可回到世界 | 有出口处理函数不等于存在可玩的通关路线 |

## 2. 新需求的落地判断表

“配置可完成”指沿用已有字段和规则，仍需维护注册清单、挂载关系并验证流程；不代表只改一段文案即可交付。“局部代码”指新增明确的函数或具名动作；不要求建设通用框架。

| 业务需求 | 当前支持程度 | 主要落点 / 设计需补齐的内容 |
|---|---|---|
| 改某名 NPC 台词、对话跳转、日期变体 | 配置可完成 | `npc-dialogues/<id>.json`；明确初始节点与规则优先顺序 |
| 按日期、Flag、物品、献祭状态开放选项 | 配置可完成 | `start.rules`、`enabledWhen`；当前选项条件控制可点击，不能直接当作隐藏选项能力 |
| 一次性赠物、交出已定义物品换已定义物品 | 配置可完成 | 条件 + `removeItem / addItem / setFlag`；明确领取标记、数量和重复访问行为 |
| 增加普通 NPC | 配置 + 接入 | NPC JSON、两类 manifest、战斗角色配置、地图事件集；无战斗者使用 `combatEnabled: false` |
| 新 NPC 可被攻击、死亡后离场、有战后奖励 | 需要局部代码 | `runNpcAction`、动作白名单、`runBattle` 奖励及对象状态判断；现有 NPC 战斗动作仅艾迪和丧钟 |
| 增加地点、分叉、隐藏路径、条件锁 | 地图配置可表达 | `world-map.js` 的节点、连线、`revealFlag / activeWhen`；还需事件挂载与可达性验证 |
| 同一地点按条件或权重出现不同事件 | 配置可完成 | `world-events.js` 的 `entries / when / weight`；当天首次选择会锁定结果 |
| 使用卡牌、物品、知识解决两三个对象的遭遇 | 基础配方可配置 | `action-events/*.json`；明确槽位、匹配、优先级、阶段和资源成本 |
| 行动引发 NPC 迁移、怪物留驻、延迟释放或特殊死亡 | 需要局部代码 | `world.js` 具名后果；已有示例有明确事件专用逻辑，不能任意换 ID 即复用 |
| 新行动事件有额外体力 / HP 成本 | 新事件需检查或补接入 | 字段校验存在，但目前成本扣除路径只覆盖五个指定测试遭遇，详见 5.3 |
| 新物品、可用物、装备 | 需要局部代码 / 数据登记 | `ITEM_LIBRARY`、使用/装备处理、编辑器选项；新装备效果还需战斗解释支持 |
| 新知识线索 | 需要数据登记及获取后果 | `ActionEventRuntime.KNOWLEDGE`、World 获取逻辑；知识条件通常借助配套 Flag 表达 |
| 沿用现有技能类型配置敌人数值与意图 | 配置可完成 | `battle-data/combatants/*.json` + manifest；验证已有战斗解释器支持的字段 |
| 新技能类型、战斗资源、助战或新献祭能力 | 新增规则 | 明确最小战斗接口与结算行为；不直接从 World 修改战斗内部对象 |
| 调整初始牌组 | 配置可完成 | `deck-config.js`；卡必须已在卡库启用 |
| 新卡牌模板与效果 | 模板 + 必要代码 | `game.js / CARD_LIBRARY`；新效果需相应结算支持，另定义获取来源 |
| 每次长休让多个地区和 NPC 演化 | 需要局部日结逻辑 | `longRest()` + 明确状态；日期对白本身不会让未访问地区自动发生事件 |
| 血肉食用、延寿、商店库存、统一交易界面 | 尚未实现 | 当前有物品和交换基础，业务需定义恢复量、期限、库存、报价及一次性规则 |
| 存档、任务日志、人物关系评分、经济或环境模拟 | 尚未实现 | 单独确认范围与必要性，不能由现有局部示例推定为支持 |

## 3. 当前可依赖的玩法规则

### 3.1 日期、体力、生命

| 项目 | 实际实现 | 需求设计注意 |
|---|---|---|
| 开局 | Day 1，体力 6/6，锈剑 ×1、止血瓶 ×1，装备槽为空 | 拥有武器不等于已经装备 |
| 完整身体 HP | 初始数据 60/60；首次世界渲染同步为 66/66 | 平衡设计以同步后的 66 为基线 |
| 日期推进 | 只有长休推进一天 | 移动、对话、搜索、行动和战斗不推进日期 |
| 五日期限 | Day 1 到 Day 5 有四次安全长休；Day 5 仍可行动，再长休触发化粪结局 | 不是进入 Day 5 立即失败；食肉与献祭没有延寿结算 |
| 长休 | 地图 HUD 常驻；恢复满 HP、满体力，清空所有卡牌疲劳 | 不依赖营地；进行中的行动事件不允许长休 |
| 首次探索 | 首次进入未探索节点扣 1 体力，自动触发事件 | 节点已显示不代表已探索 |
| 重访移动 | 已探索安全节点之间不扣体力，可沿已探索路网寻路 | 未处理行动、战斗和威胁会阻止自动穿越 |
| 战斗入场 | 通常扣 1 体力；首次到达直接遭遇可复用已付探索成本 | 不要按“探索 1 + 每场固定再扣 1”统一预算 |
| 其他成本 | 献祭、搜小屋、旧开路动作有明确体力成本；部分遭遇额外扣 HP / 体力 | 免费场景展示与实际付费行动应分开写 |
| 战后 | 回写 HP 和每张卡剩余疲劳；胜利没有固定回血 | 逃跑保留损耗；当前败北由 World 判定死亡 |

长休清空 `dailyEventRolls / dailyNpcLocations`，保留探索记录、背包、装备、献祭、Flag、知识、事件阶段和威胁。威胁可用 `releaseDay` 延迟生效；菌雾诱导用当天日期标记失效。**这两种局部行为不构成覆盖整个地图的日结系统。**

### 3.2 卡牌与疲劳

默认牌组为 **10 张实体副本、7 种模板**：

| 卡 ID | 名称 | 数量 |
|---|---|---:|
| `quick` | 短促刺击 | 2 |
| `thrust` | 穿甲突刺 | 2 |
| `heavy` | 葬仪重斩 | 1 |
| `guard` | 灰钢架势 | 2 |
| `focus` | 观察 | 1 |
| `adjust` | 调整 | 1 |
| `adjustStance` | 快速换架 | 1 |

实际启用分类为 `attack / defense / technique / ritual`，对应暴力、执念、伎俩、秘仪。观察是 `technique` 中的 `focus` 卡，行动事件单独识别；没有独立观察卡系。恢复、单张招架和闪避模板目前处于注释状态；快速换架的 0 刻效果仍启用。

卡牌模板、开局数量、世界获得来源是三个独立事项。卡库中有 `feint / preRead / chase` 等模板，不代表玩家开局或正常探索就能获得。

每张牌保存 `{ instanceId, cardId, fatigue }`。同名副本各自记录疲劳：

- 行动事件中，只有最终配方实际使用的副本疲劳 +1，可以累积；疲劳牌仍能投入事件。
- 战斗打出疲劳牌固定消耗 1 刻，只移除一层疲劳，原卡效果全部失效。
- 抽到、弃置、预读和回手不会清疲劳；剩余层数跨战保留，长休清空。
- 疲劳规则变更会同时涉及事件、World、战斗和提示文案，属于玩法修改。

### 3.3 物品、装备与献祭

物品支持获得、数量持有、查看、消耗与明确槽位装备。目前背包主动使用仅实现止血瓶，恢复最多 18 HP，不推进日期。

| 资源 / 装备 | 当前用途 |
|---|---|
| `baitMeat` 诱饵肉 | `lure` 标签的事件资源；不能食用，也不等同于新鲜血肉 |
| `freshFlesh` 新鲜血肉 | 部分来源可获得；指定事件可消耗，例如投入断手事件泥水槽脱险；没有主动回血或延寿 |
| `rottenFlesh` 腐败血肉 | 可领取并持有；当前无主动使用能力和事件标签 |
| `oldKey / ritualScrap` | 老旧钥匙 / 秘仪残页；钥匙有旧开路用途，残页与小屋奖励关联 |
| 锈剑 / 长剑 / 匕首 / 盾 | 单手装备，可选左手或右手；分别提供攻击、快攻流血或格挡效果 |
| 双手剑 | 占据两手，攻击耗时 +1，拼刀伤害翻倍 |
| 重甲 / 道服 | 身体装备；分别改变补牌格挡与冷却、保留手牌行为 |
| 礼帽 | 头部装备；当前无数值修正 |

换装不销毁背包物品，装备槽可卸下；一份同名单手装备不能同时占两手。双手装备实际占用两槽，战斗修正按装备 ID 去重。装备定义存在不保证有当前可达获取来源。

身体面板有左手、右手、身体、头、眼、心、脑七项；当前献祭菜单开放左手、心、眼、头、脑：

| 选择 | 收益 | 实际代价 |
|---|---|---|
| 完整身体 | 最大 HP 66、暴力伤害 +1、执念格挡 +2，部分正常人对白路线 | 献祭任一部位后整组加成消失，HP 上限回到 60 |
| 献祭左手 | 从当前攻击/防御卡选一个具体副本永久移出，变成 0 刻、5 刻 CD 内化技能 | 耗 1 体力，永久失去左手槽，不能继续使用双手装备 |
| 献祭心 | 解锁秘仪，缺少时加入 `bleed / delay` | 耗 1 体力、永久献祭；无新增法力条 |
| 献祭眼 | 每 8 刻生成 2–3 个双倍伤害破绽时刻 | 耗 1 体力、永久献祭 |
| 献祭头 / 脑 | 改变对白身份；两者都献祭可让丧钟认同并给钥匙 | 各耗 1 体力；头部槽损失；没有通用操虫或人格系统 |

献祭入口由 World 自动加入 NPC 对话，不依赖祭坛。限制献祭到指定 NPC、改变内化方式或增加器官能力，都需要明确提出规则变更。成长目前依赖装备、卡牌、知识、献祭与世界后果，没有 XP、等级或胜利固定三选一卡。

### 3.4 战斗能力及返回世界

World 仅通过 `BattleBridge.startBattle(enemyId, context)` 请求战斗。当前传入 HP、HP 上限、卡副本快照、开局延迟、先制伤害、知识伤害倍率；装备和献祭修正通过 `WorldGame.getCombatModifiers()` 提供。

桥接返回 `{ result: 'Win' | 'Lose' | 'Escape', playerHp, cardFatigue }`。玩家点击结果界面“回到地图”后，World 才处理奖励和世界后果。战斗临时卡不会写回永久牌组。

- 单体战有未来 3 条意图、耗时推进、抢攻打断、同时结算拼刀、韧性和 6 刻失衡。
- 初始/补牌目标手牌为 5 张；基础补牌耗 1 刻，基础 CD 为 5 刻，装备可改变补牌行为。
- 群体战当前为 6 只、每只 12 HP、每只贡献 2 伤害；有贴身/近距/远距阵线，以及扑咬、涌动、包围。少于 4 只时包围失效。
- 群体普通伤害从最近存活单位结算并可溢出；临时横扫伤害最近 3 只各 3 点、不溢出。最近 3 次出牌累计击杀至少 3 只可触发一次溃散；群战不使用单体韧性失衡。
- 开局延迟影响敌方意图队列；先制伤害只作用单体、最低留 1 HP，群战忽略。粪怪习性给两种粪怪最终伤害 ×1.15 并向上取整。
- 舞台通过本地 `vendor/` 的 Three.js 和 WebGL 呈现逼近、受击、死亡等原型反馈；不代表各角色已有完成的美术资源。

战斗奖励按 World 中的来源 ID 分支处理，当前无通用奖励表。新敌人的数据、接入地点与胜负后果应一起设计。

## 5. 内容配置如何表达需求

### 5.1 内容接入链路

```text
world-map.js：地点、连接、揭示条件、eventSetId
  → world-events.js：候选事件、when、weight
    → npc：npc-dialogues/<id>.json
    → dialogue：world.js 登记的地点处理函数
    → battle：battle-data/combatants/<id>.json + World 战后处理
    → action：action-events/<id>.json + World 具名后果
```

有一个候选时直接选中，多候选按权重抽取；当天首次选择后锁定，后续不会因为 Flag 改变而重新抽取。同一 NPC 当天只分配到一个触发地点，但这是访问时记录，不能直接作为全局日程或剧情迁移使用。

地图节点复用事件集只是共用候选定义；**多个节点复用同一个行动事件 ID 会共用 `eventStates[eventId]` 进度**。若要求“每处独立完成、独立奖励”，必须分配独立 ID 或另行实现实例化。

### 5.2 NPC 对话

每份配置含 `schemaVersion / id / name / start / nodes`：

| 字段 | 业务含义 |
|---|---|
| `start.default` | 没有规则命中时的初始节点 |
| `start.rules` | 按日期、Flag、物品或献祭决定入口；首个命中规则生效 |
| 节点 `body` 及文本 `variants` | 默认对白与条件文本；首个命中文本变体生效 |
| 节点 / 选项 `effects` | `setFlag / addItem / removeItem` 通用后果 |
| 选项 `next` | 跳到本 NPC 的其他节点 |
| 选项 `enabledWhen` | 条件控制按钮可点击；不满足时仍呈现禁用选项 |
| 选项 `action` | 执行明确登记的 World 动作，不能填写脚本 |

条件组是 `{ mode: 'all' | 'any', clauses: [...] }`，当前条件来源与运算为：

- `day / sacrificedCount`：`eq / ne / gte / lte`。
- `flag`：`exists / notExists / eq / ne`。
- `item`：`has / lacks`，可指定数量。
- `sacrifice`：某部位 `sacrificed / intact`。

不存在 HP、体力、知识或关系值的直接条件来源；需要条件时，可使用明确同步的 Flag，或扩展解释器。现有模板变量为 `day / dailyStockId / dailyStockName / sacrificedCount`。

节点 `effects` 每次进入节点都会执行，**不会自动保证只执行一次**。赠物和交易应配领取 Flag、初始规则或选项条件，防止循环对话重复奖励。`removeItem` 后果会先检查整组所需物品，不足则拒绝执行。

### 5.3 卡槽行动事件

每份配置通过 `action-events/manifest.json` 注册，包含 2–3 个对象槽、`start` 和 `stages`。每阶段配置场景文字、`recipes`；配方可含槽位匹配、条件、优先级、通用后果、结果文字和 `next`。

资源有三种：卡牌副本、带 `eventTags` 的物品、带 `tags` 的已得知识。秘仪投入要求实际拥有秘仪卡且已献祭心。知识不消耗，胜出配方使用的物品消耗一份，卡副本疲劳 +1。

当前结算约定：

1. 任意槽位出现非 `focus` 行动卡时，先排除观察配方。
2. 无效行动不能自动退回观察；目标错误或条件不足会阻止提交。
3. 其他命中配方按 `priority` 选最高项；最高项并列时阻止提交，不按数组顺序任选。
4. 只有胜出配方用到的资源参与消耗；未结算观察卡不疲劳。
5. `actionSlot` 可让单目标行动卡从任意槽匹配；多目标事件仍使用指定槽。
6. `itemOnly: true` 可允许一个物品独立结算，其他槽必须为空。

结果文字在提交后展示。设计稿需分别写“行动前可见信息”和“行动后揭示”，避免槽位名称和场景说明提前泄露结果。

**配置支持范围与执行范围要分开核对：**

- 匹配器可以校验 `staminaCost / hpCost`，但扣除和不足检查目前只在 `SLICE_EVENT_IDS` 的五个测试遭遇路径实现。新事件不能仅填这两个字段就认为成本已落地。
- `action` 是白名单，具体后果又绑定 World 中的分支及事件 ID。已有 `metal_endure` 或 `hand_strike` 不能任意贴到另一个事件即得到同样业务流程。
- `allowLeave`、特殊重访、困境死亡与战斗成本抵扣也需核对 World 的对应路径。
- 通用简单 `effects + result + next` 可以沿现有流程使用；迁移、发知识、额外成本等需明确接入。

## 6. 世界状态：持久到什么时候

这里的“持久”指**本局内存内、跨交互和长休保留**，不代表刷新页面后仍存在。

| 状态 | 用途 / 生命周期 |
|---|---|
| `day / hp / maxHp / stamina / maxStamina` | 日期和生存资源；长休推进/恢复 |
| `currentNodeId / exploredNodes` | 位置和探索记录；长休不重置 |
| `flags` | 简单后果，用 `getFlag / setFlag` 访问；需由内容自己定义写入与读取 |
| `inventory / equipment / sacrificed` | 物品、槽位、永久身体变化；长休不重置 |
| `deck / innateCardId` | 卡副本、疲劳与内化；长休只清疲劳 |
| `knowledge` | 具名知识，当前五项；长休不重置 |
| `eventStates` | 按事件 ID 的阶段、完成与局部结果；长休不重置 |
| `threats` | 节点怪物威胁及释放日期；击败后移除 |
| `dailyEventRolls / dailyNpcLocations` | 当天抽签和 NPC 分配；长休清空 |

新 Flag 需给出稳定英文 ID、初始缺省值、写入时机、读取对象和失效规则。`exists` 表示已定义，即使值为 `false` 也成立；判断完成状态通常应明确写 `eq: true`。

当前无游戏存档/读档；刷新、重开会重置本局。编辑器 `sessionStorage` 只保存制作草稿，不是游戏存档。结局主要由 Flag 和弹窗表示，若要求结局后彻底禁止输入，需要另行确认并验收。

### 示例：一次性用新鲜血肉换止血瓶

此例是**可配置的新需求示范，当前艾迪尚未接入该交易**。

- 入口：艾迪普通对话中的交易选项。
- 条件：持有 `freshFlesh` 至少 1，且 `eddiePotionTradeDone != true`。
- 成本：新鲜血肉 ×1；不推进日期、不消耗卡牌、不额外扣体力。
- 即时后果：`removeItem(freshFlesh, 1)`、`addItem(healingPotion, 1)`、`setFlag(eddiePotionTradeDone, true)`，跳到成交对白。
- 重访：选项禁用或转入已成交节点；不重复扣物、不重复赠药。
- NPC 已死：由已有艾迪死亡状态阻止进入正常交易对话。
- 验收：没肉不能交易；一次交易数量正确；循环对话与次日重访不能刷奖励。

若进一步要求“每日库存、动态报价、选项隐藏、食肉延寿”，就超出此例的简单交换范围，需要补规则或界面。

| 对齐项 | 当前事实 | 评审处理 |
