> 核对日期：2026-10-05。对象：当前工作区实际代码，包含尚未提交的修改与新增文件。Git 基准：`main / 8146c11`。
>
> 用途：作为下一轮内容与玩法需求的实现基线。本文描述现状；引用《腐蚀世界_三天VerticalSlice_节点内容大纲.md》（2026-10-04）时，将其视为内容提案，不视为已采纳或已实现的规则。

## 1. 当前项目处于什么阶段

当前是**纯前端、节点探索地图驱动的轻量 RPG 原型，内含时间轴卡牌战斗**。基本循环已具备：

`节点探索 → 对话 / 对象卡槽行动 → 战斗或世界后果 → 返回地图 → 长休推进日期`

下一轮可以复用节点导航、条件对白、卡牌/物品/知识输入、装备、献祭、跨战损耗、群体战斗。主要缺口是：**把这些能力组织成三天共享水路主线与人物关系网络**。

需要区分三个层次：

| 层次 | 当前事实 | 对设计的含义 |
|---|---|---|
| 系统能力 | 有条件路线、Flag、事件阶段、卡牌疲劳、NPC 对话、战斗桥接 | 很多新内容能沿用局部配置和具名函数实现 |
| 已挂载内容 | 托马斯路口、五个测试遭遇、艾迪、丧钟、若干探索与战斗点 | 已能验证对象行动与局部后果，但不构成新大纲的完整三天体验 |
| 留存或占位内容 | 皇帝领地、营地、管道等地图名称；旧门与出口处理函数 | 名称存在、函数存在，均不能直接等同于玩家可体验的完整内容 |

当前地图有 **43 个节点、52 条连线、3 个 Flag 揭示的隐藏节点**；事件集有 **25 份**；独立 NPC 对话有 **4 份**；行动事件有 **6 份**；战斗角色配置有 **7 份，其中 5 份启用战斗**。这些是配置数量，不是完整地点、剧情或独立怪物机制的数量。

## 2. 实际规则基线

### 2.1 日期、体力与生命

| 项目 | 当前实现 | 设计注意 |
|---|---|---|
| 开局 | Day 1；体力上限 6；锈剑 ×1、止血瓶 ×1；装备槽初始为空 | 初始有武器但需要主动装备 |
| 完整身体生命 | 初始数据为 60/60，首次渲染按完整身体加成同步为 66/66 | 应以游戏实际同步后的 66 为设计基线 |
| 日期推进 | 只有长休推进一天；探索、移动、对话、事件、战斗不推进日期 | 没有小时钟或隐性行动天数 |
| 五日期限 | Day 1→5 可进行四次安全长休；Day 5 仍可行动，再长休触发化粪结局 | 进入 Day 5 不直接失败；血肉与献祭不会重置期限 |
| 长休 | 地图 HUD 常驻，恢复满 HP、满体力，并清空所有卡牌疲劳 | 行动事件进行中禁止长休；当前不要求营地或休息点 |
| 首次探索 | 未探索节点首次进入扣 1 体力，自动触发其事件 | 揭示节点不等于已经探索；隐藏节点第一次踏入仍付探索费 |
| 重访移动 | 已探索安全节点之间移动不扣体力，可通过已探索路网寻路 | 未处理战斗/行动节点和威胁会阻止自动穿越，需单独处理 |
| 战斗体力 | 通常进入战斗扣 1；首次到达直接遭遇可复用已付探索成本 | 不应统一预算成“每场战斗必然额外再扣 1” |
| 其他成本 | 献祭、搜小屋、旧开路动作通常扣 1；部分遭遇另有 `staminaCost` / `hpCost` | 普通对话不扣费；部分环境 HP 损耗最低保留 1 HP，另有明确死亡分支 |
| 战后损耗 | 按战斗返回值回写 HP 和卡牌疲劳；胜利无固定回血 | 逃跑也保留损耗；败北由 World 显示死亡与重开 |

长休会重置当天事件抽签与 NPC 当天位置记录，保留探索记录、物品、装备、献祭、Flag、知识、事件进度与威胁。已有延迟威胁按 `releaseDay` 生效，临时菌雾诱导按日期失效；**尚无覆盖所有地区的 Day 1/2/3 世界演化结算**。

### 2.2 物品、装备与成长

- 物品支持获得、堆叠、持有判断、消耗、查看与装备；目前背包主动使用只实现止血瓶，恢复 18 HP。
- 新鲜血肉有获得来源，并可在指定事件中投入；诱饵肉与新鲜血肉是不同物品和标签。
- **当前新鲜血肉不能主动食用、回血或延寿；艾迪实际对白中也没有完成交易选项。**“艾迪只认这个”“血肉能撑更久”等文字不能视为已实现经济或生存机制。
- 单手装备可选左手或右手；一份同名装备不能同时占双手。双手剑占两手；装备可卸下，换装不销毁物品。
- 装备效果已连接战斗：武器伤害、快攻流血、执念格挡、双手剑耗时与拼刀倍率、重甲保留格挡/增加补牌 CD、道服保留手牌。
- 装备表存在长剑、盾、匕首、重甲、道服、礼帽等，**定义存在不保证当前都有可达获取来源**。
- 成长以物品、装备、卡牌、献祭、知识及世界状态为主；没有 XP、等级或胜利固定三选一卡。

### 2.3 身体与献祭

身体表有左手、右手、身体、头、眼、心、脑。当前菜单开放左手、心、眼、头、脑的献祭；并非七个槽位都可献祭。

| 选择 | 当前收益 | 当前代价 / 限制 |
|---|---|---|
| 保持完整身体 | 最大 HP 66、暴力伤害 +1、执念格挡 +2；完整身体对白路线 | 一旦献祭任何部位，这组完整身体加成消失，最大 HP 回到 60 |
| 左手 | 从现有攻击/防御卡中选一个具体副本永久移出牌组，变为 0 时刻、5 刻 CD 的内化技能 | 永久失去左手装备槽；双手装备不可继续使用；耗 1 体力 |
| 心 | 解锁秘仪使用，缺少时加入 `bleed`、`delay` | 不新增法力资源；耗 1 体力并失去完整身体加成 |
| 眼 | 每 8 刻生成 2–3 个双倍伤害破绽时刻 | 永久献祭；耗 1 体力并失去完整身体加成 |
| 头 / 脑 | 影响对白身份；同时献祭可使丧钟认同并提供钥匙 | 头部槽损失及身份后果；没有独立的通用操虫、净化或人格系统 |

每份 NPC 对话由 World 自动补充献祭入口，不依赖祭坛。目前尚未将献祭限制到温妮或某种特定宗教传播渠道。

### 2.4 卡牌与疲劳

当前默认牌组 **10 张实体副本、7 种卡**：短促刺击 ×2、穿甲突刺 ×2、葬仪重斩 ×1、灰钢架势 ×2、观察 ×1、调整 ×1、快速换架 ×1。

- 卡牌模板定义在 `game.js / CARD_LIBRARY`，开局数量在 `deck-config.js`。模板存在与加入开局牌组是两件事。
- 战斗分类实际使用 `attack / defense / technique / ritual`，界面对应暴力、执念、伎俩、秘仪。
- “观察”仍是 `technique` 类的 `focus` 卡，不是独立卡系；事件按 `cardId: focus` 单独识别。
- 单张招架/闪避牌当前被注释，未进入实际卡库；**0 时刻的快速换架仍启用且在开局牌组中**。
- 每张牌保存 `{ instanceId, cardId, fatigue }`。同名卡的不同副本分别记录疲劳。
- 事件使用实际参与结算的卡牌副本，疲劳 **+1，可累积**；疲劳牌仍可用于事件。
- 战斗中疲劳牌打出固定消耗 1 刻，只清掉一层，原卡效果全部失效。抽到、弃置、预读和回手不清疲劳。
- 剩余疲劳跨战保留；**长休清空全部疲劳**。这与附件“默认不叠加、长休不清除”的提案有直接差异。

## 3. 地图与内容现状

### 3.1 实际地图不是固定方格

当前 `world-map.js` 为 `schemaVersion: 3` 的固定节点路网，SVG 显示，支持拖动查看、回到玩家与点击寻路。节点通过 `eventSetId` 引用事件集。

仓库 `AGENTS.md` 仍写“固定方格与明确阻挡”，与当前节点实现不一致。下一轮需明确这条协作指引是否更新；本文仅记录差异。

## 4. 系统接口与业务表达能力

### 4.1 地图 → 事件集 → 对话或行动

```text
world-map.js：节点、坐标、连接、揭示条件、eventSetId
  → world-events.js：事件候选、weight、when
    → npc：npc-dialogues/<id>.json
    → dialogue：world.js 的具名地点处理函数
    → battle：battle-data/combatants/<id>.json
    → action：action-events/<id>.json + world.js 的具名后果
```

- 单一候选直接选中，多候选按权重抽取；结果在该节点当天锁定。
- 同一 NPC 一天只会被分配到一个触发地点，但这属于**访问时分配的位置记录**，不是全局 NPC 日程或按剧情迁移。
- 行动进度按事件 ID 存储；多节点复用同一个行动事件 ID 会共享该事件进度，不会天然产生独立遭遇实例。
- 已死亡/离场及已解决对象主要依赖 Flag 或事件进度判断；普通世界对白不自动全部变成一次性内容。

### 4.2 对话与事件配置能做什么

NPC JSON 支持：`start.default / start.rules / nodes / body variants / effects / options / next / action`。

通用条件支持日期、献祭数量、Flag、物品持有、器官是否献祭，使用 `all / any` 条件组。通用后果为 `setFlag / addItem / removeItem`。JSON 不执行脚本；战斗及其他特殊后果要在代码中登记具名动作。

行动事件支持 2–3 个对象槽、多个阶段、类别或指定卡牌匹配、物品/知识标签、条件与优先级、结果文本及下一阶段。当前只有标记了 `eventTags` 的物品进入事件资源面板。

结算规则：非观察行动卡会排除观察配方；行动不满足不能退回观察；最高优先级存在并列结果时阻止提交。只有获选配方使用的资源被结算，物品消耗一份，知识不消耗，卡副本疲劳 +1。`itemOnly` 支持特定物品单独提交。

“基础看场景”可使用普通弹窗免费呈现；“用观察卡调查”当前仍会疲劳。新增内容应显式区分二者。

### 4.3 世界状态与知识

| 状态 | 当前用途 |
|---|---|
| `day / hp / stamina` | 日期与探索资源 |
| `currentNodeId / exploredNodes` | 当前节点、已探索集合 |
| `flags` | 简单持久后果，以 `getFlag / setFlag` 访问 |
| `inventory / equipment / sacrificed` | 资源、装备与永久身体变化 |
| `deck / innateCardId` | 带身份与疲劳的牌副本、内化技能 |
| `knowledge` | 已获得的具名知识 |
| `eventStates` | 阶段、完成状态及局部结果记录 |
| `threats` | 某节点怪物威胁、释放日期；击败后删除 |
| `dailyEventRolls / dailyNpcLocations` | 当天节点抽签、当天 NPC 分配，长休清空 |

知识当前有粪怪习性、蠕虫养殖、菌雾节奏、菌化尸体、尸内异常。粪怪习性既能参与诱导又给粪怪伤害 +15%，最终乘算向上取整；其他知识主要影响特定调查、通行或保存线索。

**本局状态仅存在内存中**，刷新或重开会重置；没有读档/存档、通用任务日志、人格评分、水位模拟或关系数值系统。编辑器的 `sessionStorage` 草稿不是游戏存档。

### 4.4 战斗边界

World 通过 `BattleBridge.startBattle(enemyId, context)` 请求战斗。当前 World 提交 HP、HP 上限、牌副本快照、开局延迟、先制伤害及知识伤害倍率；装备与献祭效果通过 `WorldGame.getCombatModifiers()` 提供。

结果为 `{ result: 'Win' | 'Lose' | 'Escape', playerHp, cardFatigue }`。玩家点击战斗结果“回到地图”后，桥接返回，World 回写并处理奖励、死亡或逃跑。战斗临时卡不会回写永久牌组。

- 单体战：公开未来 3 条意图；牌耗时推进刻度；同时结算攻击可拼刀；有抢攻打断、韧性与 6 刻失衡。
- 当前初始/补充目标手牌为 **5 张**，补牌耗 1 刻，基础 CD 为 **5 刻**；装备可改变补牌行为。失衡时卡基础耗时变为 1，仍会叠加相关耗时修正；疲劳牌始终固定 1 刻。
- 群体战：6 只、每只 12 HP、每只贡献 2 伤害，总 HP 72；有贴身/近距/远距三层阵线、扑咬/涌动/包围。减员降低群攻，少于 4 只包围失效。
- 群体普通攻击按最近存活单位结算，可溢出；临时横扫命中最近 3 只各 3 点，不溢出；最近 3 次出牌击杀累计至少 3 只可触发一次溃散。群战不使用单体韧性失衡机制。
- 当前战斗实际启动 Three.js/WebGL 面片舞台，含逼近、受击、死亡等反馈；使用仓库内 `vendor/`，没有前端构建步骤。画面仍是原型占位表现，不是各角色完成的美术。

## 5. 与三天 Vertical Slice 大纲的对齐表

## 6. 下一轮优先确认的业务边界

1. **内容范围：**以新大纲替换当前测试地图，还是保留旧地图增加独立切片区域？哪些测试事件留下作为支线？
2. **生存规则：**五日期限保留现行触发边界；血肉具体回血与交易用途是什么？旧“食肉延寿”文字是否统一删除？
3. **疲劳成本：**保留可叠层且长休清空，还是采用附件提案？事件展示能力、基础观察、实际用牌如何区分？
4. **角色与献祭：**托马斯名称/性别统一；莫尔、温妮、小皇帝各需哪些有限状态？献祭仍可向所有 NPC 发起，还是调整传播与入口？
5. **三天因果：**每次长休与每次设施操作分别影响哪些节点/NPC？哪些变化即时，哪些只在日结发生？
6. **结尾与保底：**切片停在检修阶还是进入下一段山道？无协作、无滤布、无献祭、体力不足时，各自仍可推进的方法是什么？

新需求建议逐条给出：**对象/地点 → 可用输入 → 成本 → 即时结果 → 跨节点或次日后果 → 重访状态 → 无资源时的保底**。据此可以直接判断是配置扩写、局部具名行为，还是必须新增能力。

## 7. 文件与内容制作入口

| 文件 / 目录 | 职责 | 通常适合修改的需求 |
|---|---|---|
| `index.html`、`styles.css` | 页面、HUD、地图、弹窗、角色与战斗界面 | 玩家可见结构、文案和表现 |
| `world.js` | 本局状态、移动、物品装备、献祭、长休、地点及行动后果、战斗桥接 | 新业务规则、日结、跨节点后果与具名行为 |
| `world-map.js` | 地图节点与连线；`WORLD_MAP_BUNDLE` | 重组地点、隐藏节点、条件通路 |
| `world-events.js` | 可复用事件集；`WORLD_EVENT_SET_BUNDLE` | 地点触发哪些内容、候选权重和条件 |
| `npc-dialogues/*.json` + manifest | 每人独立对白与分支 | 新台词、起始状态、选项、Flag/物品变化 |
| `npc-dialogues.js`、`npc-dialogue-loader.js` | 共享对白校验、解释与异步加载 | 新条件/后果类型和加载支持 |
| `action-events/*.json` + manifest | 对象槽、配方、阶段和结果配置 | 新对象行动内容；特殊后果仍需 World 实现 |
| `action-events.js`、`action-event-panel.js` | 行动配置校验/匹配/加载、资源卡槽 UI | 新匹配能力或行动交互形式 |
| `card-instances.js` | 卡副本复制、疲劳形态、知识伤害乘算 | 疲劳与实例规则 |
| `game.js`、`deck-config.js` | 战斗规则、卡模板、桥接；开局牌量 | 卡能力与必要接入；避免顺带重构战斗 |
| `battle-data/combatants/*.json` + manifest、`battle-data-loader.js` | 战斗角色数值、意图、群体配置与校验 | 新 NPC 战斗或敌群配置 |
| `group-combat.js`、`battle-stage.js`、`vendor/` | 群体规则、3D 舞台、本地 Three.js | 群体与表现改动 |
| `node-editor/` | 地图编辑器、事件集编辑器、保存服务 | 编辑节点和挂载关系 |
| `npc-editor/` | NPC 对话图、属性、状态沙盒、导入导出 | 白话分支内容制作与验证 |
| `tests/` | 逻辑检查及可选浏览器回归 | 关键成本、状态、桥接和内容路径验证 |

内容制作工具的边界：

- 地图编辑器 `node-editor/index.html`、事件集编辑器 `node-editor/events.html` 通过本地服务直接保存到 `world-map.js`、`world-events.js`。
- NPC 编辑器 `npc-editor/index.html` 导出下载 JSON；需要把文件放回 `npc-dialogues/` 并维护 manifest。新人物还应登记战斗角色配置，不参与战斗时使用 `combatEnabled: false`。
- 事件集编辑器能选择/挂载行动事件；**当前没有用于编辑行动事件内部阶段与配方的完整可视化编辑器**，这些内容仍编辑 JSON。
- 新物品除 World 物品表外，应同步编辑器/解释器涉及的物品选项；例如 `rottenFlesh` 已有 World 定义，但 NPC 解释器的 `ITEM_IDS` 辅助列表尚未包含它。

## 8. 运行、验证与已知限制

```powershell
# 游戏与地图/事件集编辑器共用服务

# 地图：http://127.0.0.1:8765/node-editor/index.html
# 事件集：http://127.0.0.1:8765/node-editor/events.html
# NPC 对话：http://127.0.0.1:8765/npc-editor/index.html

# 只运行游戏，可用随机端口的无缓存静态服务
python demo-server.py --no-open
```

其他对齐限制：

- 没有构建工具、框架、包管理依赖声明或持久后端；Python 服务承担本地启动与编辑器写文件，不承担游戏世界逻辑。不要为本轮内容默认引入大型任务/事件/经济框架。
